Phase 1

已完成

目标：持久化 Session 操控

找到一种可靠方式，让主 Agent 能对子 CLI（CodeBuddy Code / Copilot CLI 等）进行多轮对话操控。 核心约束：子 CLI 会话必须支持长对话上下文保持，不能每次重新开始。

方案A：--bg 后台 Worker 模式

思路

利用 CLI 自身的后台运行能力（codebuddy --bg），启动常驻后台进程，通过管道持续通信。

  • 1.1.1 --bg + stream-json 多轮测试
  • 1.1.2 --bg + attach 行为测试
  • 1.1.3 Copilot CLI 等价能力探索
实验 & 分析
CLI测试项结果报告
CodeBuddy Code --bg 后台持久 不支持 — 任务即完成即退出 s1
CodeBuddy Code 管道多轮 stream-json 失败 — 进程 hang s1
CodeBuddy Code attach 接入会话 有条件 — 需要 TTY s2
Copilot CLI --bg 及等价功能 不存在 — & 是云端委托，非本地 s4
结论：--bg 方案不可行。CBG 的 --bg 是 fire-and-forget 而非持久进程；Copilot 根本没有本地 --bg。
方案B：PTY 终端操控

思路

用 node-pty 或 tmux 模拟一个终端，在 slave 端启动 CLI 交互模式，通过 master 端发送按键、读取输出。这是最"硬核"的方案，理论上能操控任何 CLI。

实验 & 分析
实验结果报告
tmux 操控 Windows 不可用 t1
node-pty + powershell 可用 — 能发送命令、捕获输出 t2
node-pty + codebuddy 需 bash 包装 — 直接 spawn 失败（shell script） t2-v2
ANSI 输出清洗 有效 — 能剥离控制序列、提取纯文本 t3

优缺点

优点缺点
理论上支持任何 CLI（不需要 --resume） Windows 兼容差（需要 bash 包装 + ConPTY）
可以操控交互式 TUI 菜单 输出是 ANSI 混杂流，解析复杂
可以模拟所有按键（方向键、Tab、Ctrl） 代码量大（~200 行），调试困难
PTY 作为备选方案保留。仅在遇到不支持 --resume 的 CLI 时启用。
方案C：stream-json + --resume（独立进程）

思路

每次对话启动一个独立进程（codebuddy -p），用 stream-json 收发消息。通过 --resume <session_id> 在多次调用间保持上下文连续性。

方案D：Shell / child_process 通用进程控制

思路

上移一层到 OS 级别：不依赖 CLI 自己的 --bg/ps/logs，用操作系统原语（PID、信号、重定向）统一管理所有 CLI 进程。这是方案C 的工程化封装。

实验 & 分析

核心代码（完整版见 shell-process-control.md）：

import { spawn } from 'child_process';

class ProcessManager {
  spawn(name, cmd, args): string {
    const child = spawn(cmd, args);
    const id = `${name}-${Date.now()}`;
    this.workers.set(id, { pid: child.pid, process: child });
    child.on('exit', code => this.onExit(id, code));
    return id;
  }
  isAlive(id): boolean {
    try { process.kill(this.workers.get(id).pid, 0); return true; }
    catch { return false; }
  }
  kill(id): void { this.workers.get(id)?.process.kill(); }
}

待探究问题

阻塞性（Phase 2 前必须明确）

  • session 过期时间？ — CodeBuddy --resume 的 session 多久不活动后不可恢复？
  • session 跨 workdir 有效吗？ — --resume 是否需要 --cwd 保持一致？
  • 独立 workdir 能否隔离 MEMORY.md？ — 实测验证不同目录下 auto memory 不互串
  • 子 Agent 输出何时结束？ — 可靠判定：result 消息？连续静默？新提示符？

重要（Phase 2 中解决）

  • 并发数上限 — 同一机器最多稳定几个 cbc？API rate limit？
  • 错误恢复 — 子 Agent 崩溃后如何感知和标记？
  • 超时处理 — 子任务卡住不返回的超时策略
  • stdout 缓冲 — spawn 大输出会撑爆 buffer 吗？
  • Copilot session_id 提取 — JSON 输出无明确 session_id 字段
  • 跨平台一致性 — Linux/macOS vs Windows 差异

优化项（Phase 3+）

  • PTY fallback — 遇到无 --resume 的 CLI 时自动降级
  • Sub-agent 间直通 — Agent A 结果直接传 Agent B
  • 分布式部署 — 子 Agent 跨机器运行
  • 持久化记忆共享 — 多 Agent 共享上下文
